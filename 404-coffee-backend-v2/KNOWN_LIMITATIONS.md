# Known Limitations and External Dependencies

آخر تحديث: 2026-09-12 — Africa/Cairo.

## قاعدة البيانات والتشغيل

- لا يوجد `mongod` أو Docker محلي على الجهاز، لكن بوابات Replica Set نُفذت فعليًا على MongoDB Atlas في الدفعة 28: تطبيق 231 فهرسًا، seed، integrity check، دخان حي، وتدفق مورد → مخزون → منتج → طلب → إلغاء واستعادة.
- فحص Atlas يحتاج أن يكون عنوان IP الحالي مسموحًا في Network Access. فشل الاتصال من عنوان جديد لا يعني فشل السكيما أو الفهارس.
- اتصال npm على الجهاز مر سابقًا بشهادة وسيطة غير موثوقة. لم يُغيّر إعداد SSL الدائم، ويلزم CA صحيحة لأي تنزيل حزم جديد.

## التكاملات الخارجية

- DeepSeek يحتاج مفتاحًا صالحًا واتصال شبكة. عند غيابه يعمل البديل المحلي من الكتالوج العام.
- WhatsApp منفذ كرابط مشاركة مسجل، ولا يدعي إرسالًا عبر WhatsApp Business API بلا مزود وWebhook.
- النظام Cash-only ولا توجد بوابة دفع إلكترونية حسب قرار المنتج.
- صادرات التقارير حمولة داخلية بحد 500 صف. روابط التنزيل المؤقتة تحتاج Storage provider.

## الفرونت

- تدقيق التكامل الصارم ومسارات العقد ناجحان؛ لا توجد استدعاءات production للمسارات القديمة ولا mocks إنتاجية.
- التحميل الأولي له budget آلية، والداشبورد والعملاء والمناديب والطلبات تعمل على عقود v1.
- لا توجد اختبارات Chromium/Playwright حسب قرار المشروع؛ التحقق يعتمد Vitest/jsdom والعقود والبناء.

## التشغيل الأفقي

- محددات الإساءة داخل ذاكرة العملية. التشغيل متعدد النسخ يحتاج Redis لحد موحد.
- تخزين الوسائط محلي. التشغيل متعدد النسخ يحتاج S3-compatible storage أو volume مشترك.
- Socket transport داخل العملية. التشغيل متعدد النسخ يحتاج Redis adapter أو message broker.

## بوابة الإطلاق

قبل النشر شغّل `migrate:status` و`indexes:check` و`integrity:check` والاختبارات. كل Worker يحتاج Replica Set واتصالًا مستقرًا، وتجب مراقبة Outbox وDead-letter وتنبيهات الوردية.
